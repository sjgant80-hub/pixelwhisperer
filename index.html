In plain words: type some numbers, or paste some text, and this page turns them into a small grey picture, one square per number, brighter for bigger numbers. For text, the numbers are how often each word appears, so the brightest squares are the words repeated most. That is all it does, and it says so.

The whole kernel, honestly: generatePixelArt(frequencies, width, height) maps an array of frequency values onto a grayscale pixel grid — each cell's brightness derived from its frequency, wrapping the array across the grid. Small, total, and gated. Whisper some numbers in and watch them become an image.

Looking for the card art engine? This repository also holds PixelWhisperer Kards, the deterministic pixel-art engine that draws the face of every Kardlings card, built by Kar. Its page has the gallery, the workshop, the proof and the full brochure for the people who decide (costs, security, roll-out, support).

Whisper

Whisper text

Honest scope — this is not AI summarization and it does not read the text for meaning. textToVisualSummary(text, width, height) counts how often each distinct word appears (case-insensitive), keeps the top 64 most frequent words, normalizes those counts onto the same 0–1000 scale as above, and renders the histogram through the exact same generatePixelArt — no separate rendering path. The picture shows which words repeat most; it does not show what the text means. sididy's original larger dream, across several nights, was turning dense text into visual summaries — this is the small, literal, non-semantic slice of it that a render could actually earn. Gated with the rest of the kernel: mutants killed by its own witness, re-proven on every push.

Start here

  1. Whisper numbers. In Whisper, type numbers separated by commas (0 to 1000 is the scale: 0 is black, 1000 is near white), or press a preset such as a sweep.
  2. Size the grid. Move the width and height sliders. The numbers repeat across the grid, row by row, so a short list makes a pattern.
  3. Whisper text. Paste any text into Whisper text. The brightest squares are the words it repeats most; hover a square to see its brightness.
  4. See the working. How it works runs your own inputs through each step, live.
  5. Use it in code. kernel.mjs has no imports. Copy it and call it:
import { generatePixelArt, textToVisualSummary } from './kernel.mjs';
const art = generatePixelArt([440, 880, 220, 660], 8, 8);   // { ok: true, result: rows of { x, y, color, brightness } }
const words = textToVisualSummary('cat cat cat dog dog bird', 3, 1);
if (!words.ok) console.log(words.why);                       // bad input is a refusal with a reason, never an exception

How it works

Two doors into one renderer. Text is turned into numbers by counting its words; numbers, typed or counted, become a grid of greys. Each box is a step kernel.mjs takes, in order; the second line is this page's own inputs, run through the kernel as you change them.

Adoption

What it is good for

A glance, not an analysis: a tiny, dependency-free way to see a list of numbers, or which words dominate a text (a log, a batch of support tickets, a draft), as a picture. It runs on the device that shows it and sends nothing anywhere.

How a team rolls it out

  1. Copy kernel.mjs at a named commit (no imports, no dependencies).
  2. Call generatePixelArt or textToVisualSummary and draw the cells.
  3. Copy gate.yml and kernel.test.mjs so your CI re-proves it on every push.

What it will not do

It does not summarise, read for meaning, or judge what matters; it counts. Frequencies past 1000 wrap round to dark again, and negative ones are not a colour. If you need a product with a business case, see PixelWhisperer Kards.
